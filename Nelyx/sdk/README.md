## Ownership and lifecycle

`NativeInteraction` retires a service lifetime by clearing its editors and
semantics, then notifying every still-registered observer. It reports observer
failures after notification, preserving falsey throws. Permanent disposal fences
new bindings and subscriptions before cleanup and publishes one retirement
notification; an acquired lifetime previously also published an empty update.
Returning a service lease permits a fresh lifetime with new editor generations.
Deferred general semantics actions still resolve the current callback of their
original node lifetime, but their first delivery consumes the request before
validation or user code. Duplicate/reentrant delivery, disabled or replaced
nodes and callback failure cannot replay that request.

The direct Hermes embedder now requires host ABI **2**, with `vm`, `services`,
`editing` and `semantics` capability version **1**. Supply matching SDK sources,
bundle and rebuilt host together; the older ABI fails before global installation.
`runtime/vm-environment` owns the environment once per VM and admits one app.
Timers, animation callbacks and microtasks stop at close, including late queued
callbacks. Callback exceptions and unhandled Promise rejections enter the same
error/close path. Console formatting accepts cyclic objects and BigInt and
contains failures in user serialization/getters.
After the close fence, a new timeout/interval returns an inert negative handle
and retains no callback. This also lets Hermes' Promise rejection tracker settle
handled shutdown failures without replacing the original error. New app frame
and microtask requests are rejected; admitted late callbacks are fenced.

Native GPU retirement uses its own monotonic clock/timer port after app callback
admission closes. Close the application and engine before disposing the VM
environment; pending retirement work and cancellation failures prevent successful
VM disposal. The Windows `VmCallbacks` owner holds every native timer/frame JSI
handle on the runtime thread, performs task/per-timer microtask checkpoints, and
returns those handles before VM destruction. These contracts have scoped tests;
complete fatal/graphics-loss and physical input/display acceptance remain open.

The common native owners are `runtime/native-assets`, `runtime/native-images`,
`runtime/image-memory`, `runtime/native-interaction`, `runtime/native-engine`
and `runtime/frame-clock`. Use `NativeAssetConfiguration`
and `createNativeAssetServices` with `{api, resolveSource}`. The resolver is the
host URI port; direct Hermes provides it directly, while the RN adapter captures
its actual Image module. The former RN-named asset services/types moved to these
direct subpaths; image decoding and budgets have one implementation. Native
surfaces consume the common numeric scene path; missing bindings fail explicitly.
Paragraph backends receive an immutable input descriptor; custom services must
keep their mutable working state separately. Owned run/placeholder arrays remain
immutable through layout, query and paint.

`NativeInteraction`, `NativeEditorPort` and `NativeInteractionPolicy` moved from
the former RN interaction subpath to `runtime/native-interaction`; the former
RN-named class and type aliases are removed. Windows semantics packets belong to
the Windows adapter, and RN keeps its view/control integration. `createNativeEngineServices`
assembles the shared native text, scene, picture, raster and image ports for one
AppSession. Bootstrap owns the services it creates; close the application before
disposing this engine owner. It drains the same renderer, returns an unused
startup context, then retires shared shader programs. RN bootstrap now returns
only its API/view binding; use the common engine owner instead of its former
renderer/text factory wrappers.

Copied key/focus/text observations now share the data-only Core `ui/input`
types. Windows input service/view/key queues belong to `platforms/windows`;
their shared implementation imports neither RN events nor RN Skia types. The
host supplies native keyboard-state and accessibility endpoints directly, while
the RN adapter resolves its actual modules. A semantics packet uses `surfaceId`;
the RN adapter maps its Fabric tag into this field.

Cross-adapter presentation, display migration and device loss still require separate qualification.

Windows first-load WM_CLOSE is queued until RNW reports bundle loading. Repeated requests coalesce. Late or racing React surface effects observe native closing admission and release their interaction without opening assets or a new native owner. Normal device/window destruction requires the closed/drained/zero-consumer/zero-view acknowledgement. If startup or native shutdown has failed, an explicit close terminates the app process with exit code 2; uncertain JSI/GPU owners remain retained until the OS reclaims the process resources. That path never reports a successful GPU drain. InstanceLoaded is not a first-frame or scanout signal.

The runtime checks cohort/ABI, asset hashes and byte limits, owner generations, GPU retirement, and shutdown drain. A failed drain preserves dependent resources. Complete startup/fatal/forced-teardown and graphics loss/recovery qualification remains open; see [project status](../../README.md#project-status).

Editing bindings and custom NativeEditorPort/NativeTextFieldHandle implementations must provide `blur()` as well as `focus()`. Focus exclusion calls the concrete DOM blur, React Native TextInput.blur or the existing Android editor blur command. Semantics `focusable:false` blocks focus and traversal without disabling the editor or changing its text, selection or label. Enabling it again does not automatically refocus. The portable tests and actual browser DOM checks do not qualify native IME, physical keyboard or screen-reader behavior.

Applications may include content-qualified assets exported by installed packages. `AppAsset.packageSource` contains an npm package name, its exported relative asset path and the optional notice source path. The asset and notice destinations remain app-relative. SDK CLI preparation uses the runner's installed package resolver, computes source hashes before creating outputs, copies missing files and verifies the complete manifest. Existing edited files and redirected output paths are rejected; they are never silently overwritten. The native/bootstrap and Web services continue using the copied app-relative paths and existing per-View resource ownership.

For the built-in design icons, import `materialIconFont` from `@nelyx/material/icon-assets` or `cupertinoIconFont` from `@nelyx/cupertino/icon-assets` and append them to the config assets array. Keep existing fonts/defaultFont, or set widgetApplication's defaultFont to the selected icon asset id in an icons-only app. Both fonts and their notices are packaged with their design library. This supply path requires no Dart/.NET/font tooling at product build/runtime. FontTools is used only by repository coverage checks.

Core source tooltip metadata is published separately from the accessible label as browser aria-description. Removing or excluding a tooltip clears the previous description on the stable DOM owner. Native bridge/reader qualification is separate from the browser DOM transport.

Each React Native Surface owns one bounded runtime-program cache shared by its renderer, paragraph paints, retained frame pictures and rasterization backend. Surface shutdown drains the application before releasing this cache and then its native host lease. Program wrappers that fail to retire remain owned and are not deleted twice. The cache bounds program count and source bytes; it does not certify GPU memory usage or FPS.
