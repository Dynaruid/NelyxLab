# Nelyx.FrameworkToTypeScript

초기 개발 과정의 프레임워크 → TypeScript 중간 변환 도구입니다. 제품 build/runtime과 일반 소비자는 이 도구를 요구하지 않습니다. **2026-10-19부터 개발의 기준은 제품 소스이며, 이 도구의 수정은 필요한 공통 부분으로 제한합니다.** 기능별 구현·보완은 `Nelyx/src`·디자인 패키지·해당 SDK/플랫폼 제품 owner에서 직접 진행합니다. 당시 개발 방향은 [W13 요약](../../history/26/10/19/work13-summary.md)에 보존했습니다.

허용하는 도구 수정은 여러 기능에 공통 적용되는 타입/숫자 출처·IR/emitter·출력/import·소유권/merge/edit guard·도구 호환성의 필요한 수정입니다. 기존 source path/출처/ownership 데이터는 변경 범위의 정합성에 필요한 만큼 갱신합니다. 개별 Widget/family의 누락을 위해 lowering·본문 추출/의존 closure·전용 generator/adapter/recipe·검증 기반을 계속 확장하지 않습니다. 기존 생성 소스를 직접 개발할 때는 명시적으로 adopt해 소유권·숫자 주석·license를 보존하며, 기능 수정마다 변환기 개선이나 재생성을 요구하지 않습니다.

개발 타입검사는 정식 TypeScript **7.0.2** native CLI를 사용합니다. `bun install --frozen-lockfile` 후 `bun run check:types`로 실행합니다. AST 생성/분석의 `typescript` import는 공식 `@typescript/typescript6@6.0.2` 호환 alias이며, lock에 기록된 실제 Compiler API는 **6.0.3**입니다. native CLI와 API를 분리해 유지하고 compiler identity에는 wrapper와 실제 구현 bytes를 모두 포함합니다. Bun 타입은 **1.4.3**입니다. 도입 이력은 [W12 요약](../../history/26/10/18/work12-summary.md), 유지 방침의 이력은 [W13 요약](../../history/26/10/19/work13-summary.md)에 있습니다.

2026-10-18 사용자 요청으로 `checks` 전체·fixture 및 `dart/bin/extract_platform_fixture.dart`를 삭제했습니다. 변환기 fixture/checks의 유지·복구·전체 회귀는 W13 완료 조건이 아닙니다. 도구 정리와 제품 검증 방침의 이력은 [W13 요약](../../history/26/10/19/work13-summary.md)에 보존했습니다.

기존 migration recipe가 삭제된 validator/source-comparison을 가리킬 수 있으므로 과거 `batch resume all`·validate/promote 명령을 그대로 실행하지 않습니다. 필요한 recipe를 다시 사용할 때에는 현재 제품 기준의 명시적 검증 경로부터 연결해야 합니다. 검증 누락은 실패로 유지하며 타입·숫자 출처·소유권·license 요구를 보존합니다.


현재 패키지 등록·recipe/수정 입력·생성 소유권은 `data/packages.json`과 `data/work8/`에 있습니다. 제품 build/runtime은 이 데이터도 요구하지 않습니다. W12/W13의 종료와 이관 이력은 [W13 요약](../../history/26/10/19/work13-summary.md)에 보존했습니다. 누적 실행 보고서·checkpoint·로컬 복구 archive는 긴급 정리로 삭제했습니다. 저장 위치 변경으로 과거 compiler/fixture hash를 재검증된 값으로 바꾸지 않습니다.

## 삭제 이전의 도구 설명과 검증 이력

아래 내용은 삭제 이전의 기능·제약·실행 기록입니다. `checks`·fixture·재개 명령과 과거 회귀 의무는 현재 실행 지시가 아닙니다. 현재 제품 검증 완료를 뜻하지 않습니다.

Independent, private Bun/TypeScript development tool for pinned framework ports. SDK builds and consuming applications use tracked TypeScript and do not install or run this tool.

`node tools/Nelyx.FrameworkToTypeScript/checks/base-reproduction.mjs --record`
qualifies the currently accepted batch inputs against the current Git commit,
then regenerates every accepted base in an independent checkout with no batch
cache. It records exact source spans and LF/CRLF reconstruction, checks base
hashes and verifies that composing against the reproduced base preserves a
direct product edit. Commit source/tool changes before recording. Run without
`--record` to reproduce the recorded historical revision after later edits. The
check reuses the hash-qualified local Dart SDK and installed registry
dependencies; it does not qualify a clean machine or a native runtime.
Immutable historical input records live under `archived record: base-records`.
Use `--revision <qualified-git-revision>` to regenerate a previous accepted base
after the current recipe or dependency inputs have changed.

Missing/ambiguous selections, duplicate ownership and a mismatched source pin fail planning. `resume all` processes only registered mapping-closed recipes independently; registration does not make a whole SCC executable. Recipes cover selected MatrixUtils scalar algorithms, physics comparison functions, bounce, gesture constants and the complete `TweenSequenceItem<T>`, `SpringDescription`, `DesktopTextSelectionToolbarLayoutDelegate`, `GravitySimulation` and `ClampedSimulation` declarations.

`body_ir.dart` resolves original executable ASTs using the locked analyzer, explicit Flutter/engine libraries and source spans. The TypeScript emitter uses factory AST nodes. Nullable scalars, ordered const initialization and explicit host constructors/assertions/Duration units have dedicated rules. Unsupported declarations block their module. The source oracle uses actual pinned AST bodies and vector_math; its Offset/Rect receivers carry scalar data and do not qualify the Dart UI engine.

The first whole data-class rule carries resolved type-parameter/field/interface identities and arguments. It supports one ordinary field-formal constructor, final public fields, positional or all-named parameters, generic/nullable field types, constructor assertions and an explicit immutable-field host adapter. `typeBindings` map a qualified Dart interface to an explicitly imported TS type. Unsupported members block the entire class. The `tween-sequence-item` fixture compares both assertions modes against the unchanged class, checks identity/immutability and strict generic/null/required/readonly consumer typing, and verifies that an unsupported neighboring class produces no partial IR. Source const object construction requires canonicalization and remains blocked; Duration retains its scalar adapter. No Dart VM or const canonicalization acceptance is inferred from a const constructor declaration.

Whole classes also admit resolved instance/static methods, getters/setters and non-generic named constructors. Named generative constructors evaluate resolved field initializers in source order; factories retain their complete bodies. Generic named/static construction and unsupported bodies still block the whole declaration. Exact qualified constant mappings and receiver-first adapters avoid guessing from display text. Opt-in safe-number integers check computed values and scalar constructor/method/function/closure parameters. Prefix/postfix and +=/-=/*= integer mutations preserve receiver/index/getter/RHS/setter order and validate before committing storage. Indexed plain assignment still requires a range-checked setter adapter; arbitrary Dart integers are not silently mapped to JS numbers. The SpringDescription fixture compares the complete unchanged class in both assertions modes, one-digit formatting/rounding and the preserved real spring solutions.

### Stateful classes and generated inheritance (W10)

The class IR is no longer restricted to immutable data classes. It carries mutable fields, declaration initializers, nullable default initialization, constructor bodies, abstract methods, explicit super arguments, and getter/setter distinctions. Mutation targets use the analyzer's resolved write element/type rather than the often-empty identifier element on a compound assignment. Expression-bodied void methods/setters discard their expression result.

`src/class-model.ts` owns the generated class graph, base-before-derived ordering, inherited member resolution, library-private names and constructor-safety checks; `dart-emitter.ts` prints that model. Classes selected into the same emission can extend one another, including generic and abstract bases. Separate modules still use explicit imports/type bindings and the exact `superConstructors` host contract. Both implicit and explicit host super calls retain `policy: 'no-derived-state-observation'`; named host arguments use the opt-in `namedArguments: 'options'` mapping. Generated constructors/methods lower positional and named arguments together, retaining source evaluation order. Super-formal forwarding supports required parameters and inherited scalar/null or resolved enum defaults; other non-scalar inherited defaults remain unsupported. A required super formal does not inherit the optional parent default.

Fields and initializer-list expressions are evaluated before the base call and committed after it. Constructor bodies run after initialization; only final fields are protected. Generated base constructors are admitted only when analysis proves that their body does not expose `this` or call overridable behavior before derived fields are committed. A base constructor that invokes an override remains blocked: simply translating it to JavaScript `super()` would change Dart initialization semantics. Private instance and static member names carry a stable library identity, allowing access within a Dart library and separating equal private names from different libraries. They are implementation names, not a security boundary or a new public API.

Resolved `implements` clauses retain their generated/imported TypeScript contracts; interface members do not become superclass overrides. Synchronous non-generic function types, closures (including captured state and lexical `this`), positional/optional/named callback calls, and returned callbacks retain resolved types. Cascades evaluate their receiver once, preserve written section order, and return that receiver; null-aware cascades skip the sections entirely. Runtime null assertions throw before invocation arguments are evaluated, including release mode. Direct null-aware properties, while loops, unlabelled break/continue and constant/enum switches are supported. Nonempty switch cases end implicitly, matching Dart, while empty labels share the following case. Numeric callback provenance survives public declarations.

Mixin applications with an explicit superclass carry their resolved ordered types. `superConstructors.mixins` must match that exact order and generic identities before an existing host superclass may implement the boundary; mixin bodies are not silently discarded or synthesized. Static constants are dependency-ordered within the class and protected at runtime. Local function declarations preserve lexical `this`/`super`, and throw expressions preserve the thrown value.

Async methods/functions/closures require an explicit `asyncRuntime` host-promise type binding; for-in and list collection-for require a reviewed `iteration` boundary. Generic calls require exact `adapters.typeArguments` specializations, rather than erasing arbitrary generic meaning. The wheel controller uses lazy checked position casts, live iteration with concurrent-length checks, and the default `Future.wait<void>` wait-all/first-observed-error behavior. Source comparison uses settled checkpoints, not Dart Zone or arbitrary microtask equivalence. Suspension inside synchronous lowering expressions remains rejected.

Non-generic instance method tear-offs require an imported methodTearOff receiver/method identity boundary. The shared Core WeakMap cache preserves listener add/remove identity across generated modules, virtual dispatch, lexical super implementations, named/default arguments and one-time nullable receiver evaluation. Host method adapters must retain stable implementation identity and the matching options calling convention. Generic methods and arbitrary call adapters remain blocked. Covariant monomorphic class parameters emit runtime checks using generated class identities or explicit imported predicates; unsupported generic/runtime types are diagnosed.

Remaining explicit boundaries include unbound/general mixin bodies, late/static mutable state fields, redirecting constructors, named generative bodies and generic named construction, partial accessor overrides requiring inherited forwarding, field-initializer names shadowed by constructor parameters, non-enum object inherited super defaults, generic methods/callbacks, generic/unbound method tear-offs, compound null-shortening selector chains, and unsupported control-flow/async semantics. Unsupported declarations produce diagnostics, never stubs. This extension does not establish full wheel/viewport or full Dart-language support.

### Nelyx contracts and numeric provenance (W9-02)

The eight recipes carry a versioned `contract`: selected public APIs, required behavior, numeric policy, ownership, intentional differences and a bounded performance workload. `classification` is `compatible`, `nelyx-replacement`, `nelyx-only` or `excluded`; excluded recipes cannot promote. These are design decisions, separate from execution statuses. `validation` is the mandatory Nelyx fixture. Optional `sourceComparison` runs independently and records `PASS`, `FAIL` (with the diagnostic) or `notRun`; it cannot turn an Nelyx failure into a pass. Existing recipes without a contract retain their historical gate. The shared `checks/nelyx-batch.ts` asserts explicit expected values, errors, ownership and receiver order without executing Dart. The original fixtures remain reference comparisons. A warm 2,000-operation kernel budget is a host regression check, not a native/FPS qualification.

The existing module imports, exact adapters, type bindings, superclass policies and tracked `manualDeclarations` define the generated/independent implementation boundary. No selected public signature was removed for this policy change. Future replacements must update their contract ID and describe the changed behavior and consumer migration in `differences`; an unselected Flutter declaration is not automatically excluded or counted as an Nelyx requirement.

`body_ir.dart` supplies analyzer-authored numeric provenance, including `int`, `double`, `num`, `BigInt`, nullable and nested collection types, inference origin and numeric generic bounds. The emitter writes `@dartType`, `@dartParam <original name>` and `@dartReturn`, plus `@dartTypeOrigin`, `@dartParamOrigin`, `@dartReturnOrigin` and `@dartBound`. Each local declaration owns its own comment; constructor options retain the Dart argument names. Initializer temporaries carry their resolved expression type. Public tags survive declaration emit; optimized JavaScript need not preserve comments. A missing Dart return annotation that resolves to `dynamic` stays unsupported, even if the expression looks numeric.

These tags do not implement a numeric runtime ABI. Existing explicit safe-integer/number/Duration mappings remain responsible for actual representation. Numeric collections use qualified `typeBindings`; BigInt is tested as an explicitly imported bigint type and identity pass-through, not newly supported arithmetic. `checks/numeric-provenance.ts` runs the real analyzer on the tracked Dart fixture, checks AST attachment, `.d.ts`, determinism and numeric/collection runtime boundaries. Batch lifecycle checks exercise direct-edit preservation and conflicts; adopted files remain independently owned and cannot silently receive regenerated content.

Historical automatic reviews are never copied forward merely because a destination hash still matches. They are recreated by the current accepted-batch reader; dependency, tool or fixture drift returns the declaration to its unresolved status. `checks/coverage-evidence.ts` exercises this rule and the separate preservation of reviewed manual/notApplicable entries.

`checks/text-style-source.mjs` runs the unchanged whole pinned TextStyle class in both assertion modes with explicit engine/value/diagnostic receivers. `checks/text-paints.mjs` checks actual Root/SkParagraph Paint pixels against an independent paragraph, direct/retained DPR1/2/3, native TS/JSI-web Paint receivers, image ownership, cache checks and failed construction. `checks/text-style-consumer.mjs` installs the supplied core archive outside the repository and checks standard NodeNext declarations, direct ESM and subclass initialization. Native JSI execution, full UI paragraph/strut/hyphen contracts and final platform acceptance remain separate.

The development-only `checks/implicit-animations.mjs`, `text-transitions.mjs` and `paragraph-pictures.mjs` group manual-port acceptance by actual State/render flows. They distinguish unchanged pinned Dart declarations with explicit receiver boundaries, real locked vector_math, deterministic Root text receivers, actual CanvasKit CPU glyph/picture pixels and separate browser observations. The pixel check covers mixed Korean/Latin at DPR 1/2/3, direct versus retained rendering, advisory bounds, the RN web recorder and resource retirement. These checks do not qualify generic/mixin compiler lowering or native host/FPS/reader acceptance.

## Legacy selected C# drafts

Install Bun, a .NET SDK with the .NET 10 targeting pack (Roslyn comes from that SDK), and run from this directory:

```powershell

bun run port --language=csharp ../../Nelyx/upstream/framework-imports.json C:/Users/parti/Labo/DorotiLab ../../.tmp/work6/my-port
```

The source checkout must match the manifest hashes. Output must be a fresh directory below repository `.tmp/work5/` or `.tmp/work6/`; product sources are never generator output targets. Existing drafts are not overwritten. Every scratch ancestor is checked for links before creating directories. Selection IDs distinguish repository/language/source-qualified symbols; identically named symbols in separate libraries produce distinct draft names. SourceReader uses Roslyn syntax and semantic APIs, with framework references intentionally unresolved in isolated selections; unresolved diagnostics block automatic generation. Reviewed ports retain the AST, dependency list and source locations for manual lowering. .NET and Bun are development dependencies of this tool only.

Automatic rules currently cover a non-generic C# class, get-only properties, numeric/boolean/string fields, constructors, local declarations, expression/return statements, arithmetic, conditional expressions and explicitly mapped Math calls. The TS compiler AST printer formats drafts. Integer division, overloaded/value equality, named/ref arguments, runtime generics, inheritance, async/microtasks and unrecognized statements require review. They are never replaced by `any`, empty methods or invented defaults. An `excludeMembers` entry explicitly omits a member from the draft and must be reviewed before adoption.
