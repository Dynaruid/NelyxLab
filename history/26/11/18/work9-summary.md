# Windows 와이드 Demo 일반 스크롤 끊김

원문 `work9.md` · 작성·실행 2026-11-18 KST · 소스 분석 `deb611aa` · 보관 11-20 · 원문 스냅샷 `ffe5c5a2`

**PARTIAL · `performanceAccepted=false`**. 사용자가 Windows Demo의 `All components` 와이드 2열에서 끊김을 보고했다. 30 FPS는 당시 체감치였고 입력 장치와 어느 열인지는 미확인 상태였다.

## 측정과 원인 선별

- 60Hz에서 휠당 48 논리 px를 보내며 실제 layout의 extent를 기준으로 각 열을 끝까지 왕복했다. 반대 열 고정·복귀 위치를 확인했다. desktop 이동 간격 p95와 30 FPS 예산 초과 시간, 100ms 이상 간격·진행 정체를 봤다.
- Windows Semantics의 패킷 비교 3쌍에서 왼쪽 첫 하강의 desktop 하한은 44.96 → 41.46 FPS, 이동 p95는 50.13 → 62.89ms였다. 후속 캡처 경로에서 게시 레코드를 줄여도 브리지·UI 적용 p95의 감소를 입증하지 못했다. 고정 목록의 일부 작은 차이에는 송신기 또는 별도 빌드의 교란이 남았다.
- 대표 긴 프레임은 왼쪽 1,152px에서 `Text fields`가 처음 들어오는 시점이었다. 슬롯 생성 **37.49ms**, 이를 포함한 layout **57.62ms**, Scene **82.45ms**, 같은 commit의 UI 적용 **0.236ms**였다. 다른 재하강에는 새 슬롯 없이 paint 22.33ms가 관측됐다.
- 열별 dormant 슬롯 4개 보존은 첫 하강 p95와 초과 시간을 세 쌍 모두 줄였으나 157.42ms 하강, 122.29ms 복귀 간격이 남아 적용하지 않았다. 기본 정책의 별도 첫 하강도 24.59 FPS와 100ms 이상 간격 2회를 기록했다.

## 제품 확인과 한계

최신 Core·SDK를 공급해 두 열의 왕복·편집·테마·resize·UIA TextPattern 좌표를 확인했다. Testbed는 상태를 읽을 수 있게 노드를 붙여 행 8의 선택·해제를 확인했다. 실제 고정·가변 목록은 양 끝의 UIA 구성과 복귀, 100ms 이상 간격·정체 0회를 확인했다. 달력 3회는 입력과 월 정착을 통과했으나 desktop 하한 중앙값 28.42 / 23.64 / 15.85 FPS, 빠른 역방향 정체 8 / 6 / 7회였다. 물리 정밀 터치패드, scanout, 실물 IME 후보 창 위치와 GC 기여율은 미확인이다.
