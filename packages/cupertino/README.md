# @nelyx/cupertino

Selected cupertino widgets on a single @nelyx/core 0.16.0 instance. Import directly from `@nelyx/cupertino/widgets`. This package owns its implementation and notices; it does not claim the complete Flutter design library. The common AppTheme/AppThemeData in core remains an Nelyx host adapter, not Flutter's canonical design theme.

Source imports use public core subpaths; emitted modules and declarations require no Dart, generator or scratch files.

`form-row`/`form-section` and `widgets` export canonical `CupertinoFormRow`, `CupertinoFormSection` and their option types. Rows provide source directional padding, a loosely flexible trailing child, prefix/helper text roles and an error slot. Sections provide standard/inset-grouped constructors, 13px secondary header/footer text, margins, decoration and clipping; the existing CupertinoListSection owns dividers and group painting. Use a GlobalKey when moving a stateful row between the different standard/inset ancestor trees. The testbed consumes these APIs with CupertinoTextFormFieldRow. Complete editing/restoration and native font/IME qualification remain W14 work. Source and scope: `licenses/form-widget-sources.json`.

`button`/`widgets` share `CupertinoButton` and `CupertinoButtonSize`. Options accept a Widget child, press/long-press callbacks, external focus/state controllers, plain/filled/tinted colors, three size defaults and pressed opacity; `(id, label, onPressed)` remains supported. The button resolves live Cupertino theme/dynamic colors and text, including dark tinted opacity and the small text role. Core owns keyboard/pointer/semantic activation and cancellable press motion.

`checkbox`, `radio`, `switch` and `widgets` export controlled `CupertinoCheckbox`, `CupertinoRadio<T>` and `CupertinoSwitch`. Checkbox supports source tri-state cycling. Radio consumes Core `RadioGroup<T>` through an explicit group type token, or an external registry; group traversal preserves current reading order, arrow wrap and disabled skipping. Switch uses the pinned Cupertino drag hysteresis and RTL direction. Shared Core owns source WidgetStateProperty/StatesController, focus/actions, gesture arena, ticker/position animation and source semantics. Stable ids retain source flags/actions; tap events use an explicit per-View messenger. Caller nodes/controllers/registries remain caller-owned. The selected rounded mark painters and opacity motion do not yet implement the complete original superellipse/focus/gradient/ink/haptic APIs.

`@nelyx/cupertino/colors` also exports all 47 pinned `CupertinoColors` fields and their eight brightness/contrast/interface-level variants, generated through the existing resolved Dart pipeline. Palette aliases and plain Color constants retain shared Core identities.

The `widgets` and `theme` entries export the same inherited `CupertinoTheme` class. Both `new CupertinoTheme(data, child)` and `new CupertinoTheme(child, appThemeData?)` are supported. Canonical themes resolve platform brightness, contrast, elevation, scaffold/bar colors and default text on the Core tree. `NoDefaultCupertinoThemeData` preserves nullable construction specifications. `copyWith` retains specified versus derived values; repeated resolution keeps dynamic color variants. Theme color inputs accept shared Core Color objects or ARGB numbers, and public color getters/Core TextStyle colors expose ARGB. `brightness` is Nelyx's effective getter; `specifiedBrightness` and `noDefault()` retain source null. `@nelyx/cupertino/text-theme` supplies all nine pinned roles and explicit Core TextStyle overrides. Full text-color object APIs and font delivery remain separate.


`@nelyx/cupertino/scrollbar` exports `CupertinoScrollbar`; `colors` exports the complete `CupertinoDynamicColor` class and its public source const factories; `interface-level` exports `CupertinoUserInterfaceLevel` and `CupertinoUserInterfaceLevelData`. The widget aggregate also exports these classes. All use the same Core RawScrollbar, ColorProperty and runtime type/const domains, with no dependency from Core into a design package.

The complete source APIs retain brightness, contrast and interface-level resolution, inherited dependency updates, drag thickness/radius animation and owning-View haptic requests. Mount scrollbar widgets under the application's Directionality/MediaQuery contracts. The theme subpath supplies the inherited CupertinoTheme contract; physical haptic delivery remains a separate qualification scope.

`@nelyx/cupertino/scroll-behavior` and the widget aggregate export the complete pinned `CupertinoScrollBehavior`, retaining Core identity, desktop scrollbars and source macOS physics. Install it through `ScrollConfiguration` or the new `CupertinoApp` from `widgets`/`app`.

`CupertinoApp({home, theme, locale, supportedLocales, ...})` composes shared Core WidgetsApp, MediaQuery, locale/RTL, Overlay/Navigator, base interface level, resolved CupertinoTheme/default text/selection, scroll behavior, application focus/shortcuts and Hero scope. `child` supports a custom routing subtree. `initialRoute` accepts a Core Route or route name; `routes`, `onGenerateRoute`, `onUnknownRoute` and `onGenerateInitialRoutes` use the shared Core route contracts. Named deep links build prefix stacks, omit missing intermediate routes and fall back to `/` when the final target is missing. `navigatorController` is optional; mounted controllers support named pushes/replacements and retain State when locale/theme changes. Route restoration uses `restorationScopeId` and `navigatorRestorationId`, resolving saved names through the same table/factories. Typed fields use the same scope/manager. No global owner is created. Custom `builder` runs under the theme.

`CupertinoApp.router({routerConfig, ...})` accepts typed Core RouterOptions, including provider/parser/delegate and an explicit error callback. NavigatorRouterDelegate receives an automatic Hero scope. Providers, delegates and external controllers remain caller-owned. Locale callbacks run list-first, then single-locale, then the pinned basic matching algorithm. Core `canonicalLocaleTag` normalizes the pinned 78 language/6 region aliases; app tags preserve supported-string spelling for message keys. Home and table-defined named routes use the canonical CupertinoPageRoute with 500ms transitions, back gestures and preserved Core RouteSettings. Explicit Route instances and onGenerateRoute/onUnknownRoute results retain their route owner. Full localization delegate data and OS chrome/inspector remain incomplete; these selected Core APIs do not claim the complete Flutter constructors.

`activity-indicator`/`widgets` export `CupertinoActivityIndicator`, its `partiallyRevealed` factory and `CupertinoLinearActivityIndicator`. The pinned eight-tick alpha/rotation and partial reveal geometry run on the owning Core ticker and painter; animating changes retain State and release the owned ticker on removal. The circular color/animating/radius/progress fields have public getters. The circular default color resolves brightness as in the source. Explicit colors and linear defaults follow the source's unresolved color path. Radius and partial/linear progress bounds are checked. These widgets do not infer physical native/GPU/FPS acceptance.

The positional button's public `id`, `label` and optional `onPressed` getters are retained. Options-based children without explicit ids/text throw when their absent string metadata is requested.

`slider`/`widgets` export the controlled `CupertinoSlider({value, onChanged, min, max, divisions, activeColor, thumbColor, ...})`. `thumb-painter` exports the original circular thumb painter, slider/switch shadow lists and radius/extension constants. The slider uses the owning Core horizontal drag recognizer and distance-scaled discrete position animation, thumb-only hit region, original interpolation/callback and semantic adjustment decisions. It retains the source's lack of a keyboard focus wrapper. Edge haptics use only the owning View's explicit messenger; physical delivery is unverified. Equal min/max is disabled with a zero fraction, a finite host boundary rather than the source's zero-span NaN path. Browser ARIA preserves percent text and separately carries the actual numeric range; assistive readers/native delivery remain unverified.


`icon-theme-data`/`widgets` export `CupertinoIconThemeData`, extending the canonical Core IconThemeData and preserving subtype-copy and ambient dynamic color resolution. The pinned class reapplies Diagnosticable; its diagnostic output contains only its own color property. That mixin order is preserved. Core IconTheme resolves dynamic color before filling fallback fields. Original native bodies and actual Root lookup checks cover this scope; Icon glyph rendering and icon font delivery remain pending.


`icons`/`widgets` now expose the complete pinned 1,322 Cupertino definitions and source font/package constants on the canonical Core IconData. Getters create constants lazily and preserve source alias identity. `Icon`/`IconOptions` are the same Core widget exported by both design aggregates. It uses actual RichText, source theme opacity/variations/foreground/shadows, one application of optional nonlinear text scaling, RTL mirroring only for directional icons, friendly source semantics and glyph exclusion. Source diagnostics retain all eleven fields. Full JS/font subsetting is not claimed.

`icon-assets` exports `cupertinoIconFont`. Copy this metadata as JSON into the root `package.json` → `nelyx.assets`; the current SDK/Metro/CLI verifies the package font and notice and copies them to the declared app-local paths before generation/build/serve. Existing edited app files are preserved and rejected on mismatch. Keep your existing application defaultFont, or select this font asset id for an icons-only application. Each View registers and retains its own fonts through the existing paragraph provider. No global font loader or sample-only registration is required.

The original Cupertino TrueType font and MIT notice are included unchanged. Every current catalog code point has a non-.notdef cmap entry. Independent unchanged original native catalog/constant/build decisions, actual Core CPU glyphs, SDK asset preparation, real Chromium CSS/Skia/DOM and public archives have separate receipts. Full chip widgets/Tooltip, font subsetting, all-glyph raster goldens, native artifacts/readers/physical/GPU/FPS remain open.

`list-tile`, `list-section` and `widgets` expose CupertinoListTile, CupertinoListTileChevron, CupertinoListSection and the canonical CupertinoListSectionType. The base/notched tile takes Widget title/subtitle/additionalInfo/leading/trailing slots, directional padding, source leading geometry and single-line text roles. Existing positional `(id, titleString, onPressed)` construction creates a Text title and forwards to onTap; the public title is now Widget. Async onTap retains its activated background until successful completion while mounted. Rejection is reported through the owning host error channel and retains the pinned source active latch.

ListSection supports base and insetGrouped defaults, header/footer, horizontal dividers, optional BoxDecoration, margins, dynamic colors and source clip modes. The private selected ClipRSuperellipse composition uses the canonical Core superellipse path for paint and hit testing; full public RSuperellipse is separate. Source constructor assertions are enforced in host modes. Original finite Dart body comparisons, actual Root/CPU/glyph/input and offline public package consumption are separate evidence scopes; native hierarchy, reader/physical delivery and GPU/FPS remain open.

`checkbox` and `widgets` share CupertinoCheckbox with all14 nondeprecated fields and the source14px mark. Default tap bounds are44px on mobile and14px on desktop, with an explicit Size override. Dynamic colors, state side/cursor, shape, dark gradients, check/dash, press and focus paint follow source decisions. Controlled values paint directly; pointer taps preserve focus and keyed moves preserve held interaction. Deprecated unused inactiveColor is removed. Native finite-source, actual CPU Root, RN Babel and offline public-package checks are scoped separately. Full Radio/Switch and list wrappers remain open.

W12 module ownership: `widgets` contains explicit value/type exports only. Each feature is defined once in its canonical module. CupertinoNavigationBar, CupertinoPageScaffold, CupertinoTextField and CupertinoAlertDialog live in `nav-bar`, `page-scaffold`, `text-field` and `dialog`. Radio and Switch have separate modules. Combined implementation paths were removed and consumers updated. Public aggregate imports remain supported. Internal helpers now live under `internal/<family>` and retained generated data/bodies under `generated/<family>`. Canonical feature/catalog/asset facades retain one definition owner. Full API/behavior parity remains W14 work.

Current structural verification uses `npm run check:package-boundaries`, `npm run check:design-ownership` and `npm run test:design-structure` from the repository root. Generated output guards and numeric provenance remain separate from full feature/native qualification.

`radio` and `widgets` expose CupertinoRadio and CupertinoRadioOptions with all 12 nondeprecated constructor fields/default getters, typed Core registry/focus/input, the 18px source paint bounds, circle/checkmark styles, disabled/light/dark colors and gradient, press overlay and focus outline. `fillColor` is the source Color field; the earlier finite state-property interpretation was removed. Explicit Nelyx ARGB color ingress is normalized to canonical Core Color. Fifteen analyzer-resolved constants have a protected generated owner under `generated/radio`; Widget/default resolution and painter remain separate under `internal/radio`. Material Radio.adaptive consumes this same implementation. Source expectation tests, real Root lifetimes and CanvasKit CPU replay pixels are scoped evidence; full Switch/native/physical delivery remain open.

Shared Core radio semantics follows the actual Foundation platform independently from the design Theme.platform. On iOS/macOS it supplies the selected flag and a localized hint only while unselected. The protected Core hint table covers all 120 pinned Widgets localization classes plus two explicit Chinese regional routes; app Localizations overrides and locale updates remain per tree. This supplies the radio field only, without claiming the entire WidgetsLocalizations API or screen-reader qualification.

The Material theme bridge uses protected raw-specification/default-resolution adapters on CupertinoThemeData. These host adapters preserve dynamic colors and separate resolved ARGB defaults from explicit overrides; they are own implementation contacts, not new Dart public APIs. Raw noDefault/copy retains source specifications while Material supplies derived primary/scaffold/selection values.

CupertinoSwitch now supplies all 23 eligible source constructor arguments, a canonical StatefulWidget, controlled 0.7/0.2 drag hysteresis, source 200ms position/300ms reaction and colour curves, theme/focus/state-colour policy, accessibility on/off labels, outline/icon/image/error and View retirement. It shares the real switch painter in Core with Material through explicit policy inputs and uses the current View messenger for iOS light-impact calls. Generic outline doubles retain DartDouble. Deprecated activeColor/trackColor aliases are excluded. Pins and qualification scope: `licenses/cupertino-switch-sources.json`; native/physical haptics, UI and readers remain separately unverified.

`route` supplies source CupertinoPageTransition and CupertinoFullscreenDialogTransition with required primary/secondary animations, child and linearTransition. It uses canonical Core curves/SlideTransition/DecoratedBoxTransition and an internal source edge-shadow Decoration/BoxPainter, including RTL and borrowed listener retirement. Full Cupertino route/back-gesture/default builder and native/physical qualification remain partial.

CupertinoRouteTransitionMixin, CupertinoPageRoute and CupertinoPageTransitionsBuilder implement 500ms route policy, previousTitle notifier and the edge back-drag detector/controller with source 350ms completion policy. They use the existing Core route/controller/gesture arena; MediaQuery.safeArea is the current host padding contact. Source comparison uses finite parent receivers; actual Core arena, offline delivery and hardware WebGL evidence are recorded separately in work12 Cupertino routes verification; page-based Router/full ModalRoute/native/physical behavior remains separate.

`text-field`/`widgets` now expose the Stateful object API `new CupertinoTextField({id, controller?, placeholder?, ...})`, `borderless`, `CupertinoTextFieldOptions` and canonical OverlayVisibilityMode values. The positional facade was removed. Rounded light/dark/disabled decoration, padding, a baseline-aligned placeholder, prefix/suffix/clear text visibility and suffix priority compose the real Core editor. Clear uses 115 pinned Cupertino locale labels, emits one onChanged callback and retains Undo. Options include caller/owned controller and focus, plain font style/alignment, keyboard/capitalization/autofill, maxLength/formatters, fixed/ranged/expanded lines and completion callbacks. Native composition remains authoritative. Matching Android editing replacement protocol2 explicitly cancels composition and restarts the IME connection as part of replacement; other hosts reject active-composition replacement. Clear callbacks and Form reset run after authoritative application, and pending callbacks retire with the editor.

`text-form-field-row`/`widgets` provide CupertinoTextFormFieldRow on the same Core TextFormFieldState and Form registration. It composes a borderless field with CupertinoFormRow prefix/error/padding, validation/save/reset and onFieldSubmitted. Reset calls onChanged after the Core state reset, following the source. A controller excludes initialValue; only omitted controllers/focus are disposed. Switching a borrowed controller to an owned controller retains text and UTF-16 directional selection, starts fresh history and retires the previous editing connection. Full strut/caret geometry, custom cursor/obscuring policies, selection/toolbar/magnifier/spelling, restoration and native font/IME/physical parity remain PARTIAL. Host styles still reject unsupported paint effects/features. Source, ARB hashes and scope: `licenses/text-input-sources.json`.
